# @alcove/testkit

Test-only material that more than one workspace's test tree needs and that `@alcove/core/testing` cannot carry. Private, never published, no build step and no `dist`: its `exports` map points at `./src/*.ts`, so a consumer resolves the source through `node_modules` and typechecks it inside its own program.

Nothing here runs in production, and nothing here is a place to put a helper for tidiness. The admission rule -- a second workspace's test tree genuinely needs it AND it cannot take the `@alcove/core/testing` channel, one explicit subpath per subject -- is in [docs/TESTING.md](../../docs/TESTING.md#shared-test-material); the decision behind it, and the measurements it rests on, are in [docs/notes/cross-workspace-test-material.md](../../docs/notes/cross-workspace-test-material.md).

## Subjects

- `./loopbackTlsCert` -- a self-signed certificate for a loopback test server, minted by shelling out to `openssl` because Node has no certificate-issuing API, and `null` where this environment cannot mint one. The broker's suite serves HTTPS with it, the web suite's relay fallback cases dial `wss` under it, and the CLI's live one-command acceptance leg terminates TLS in front of its broker with it. It reaches for `node:child_process`, so the `@alcove/core/testing` channel would put a shellout into a bundle the web app loads in a browser.
- `./nativeSshd` -- a native OpenSSH `sshd` spawned as an unprivileged child serving `internal-sftp`, in the hardened profiles, with an ed25519 or ECDSA P-256 host key, extra directives, and keys authorized while it runs. The CLI's SFTP integration suite runs against it, and the web browser suite's SSH client cases dial it through the SFTP relay. It spawns `sshd` through `node:child_process`, so it cannot take the `@alcove/core/testing` channel.
- `./prerequisiteGate` -- the CI-detection predicate and opt-out constant that decide whether an absent test prerequisite is a reported skip or a failed run. The web and broker suites' gates and the CLI's live one-command acceptance leg each declare a prerequisite against `loopbackTlsCert` above, so they read this from the same place their certificate comes from rather than each carrying its own copy of the CI rule.
- `./waitFor` -- a wait on a condition through `vi.waitFor` that fails naming the condition rather than as the test's own timeout. The web suites and the broker's suite both poll with it, and it imports `vitest`, which `packages/core` does not declare.
