- - -> The ids change only when the shared secret does.
- - -> A successful handshake rotates the secret (see [Shared-secret rotation](#shared-secret-rotation)) and so moves both ids, while a scheduled window the partner does not meet leaves them unchanged, and every later attempt registers the same ids at the coordination server until a handshake succeeds or the exchange is re-invited.
- - -> The server can read the partnership's liveness and cadence from that repetition, never its content.
- - -> The derivation takes no window or clock input, so two parties holding the same secret derive the same ids without agreeing on anything else; the operator's account of a missed window is in [A missed window is neither desync nor attack](../MANAGED_EXCHANGE.md#a-missed-window-is-neither-desync-nor-attack).
