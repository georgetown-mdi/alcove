# triggers and what it shows, and the channel-open Budgets row covers a
# browser run's expiry too.
- - -> A browser run that lists them races its listen or dial against them the same way, on [the web application's client](WEBSOCKET_RELAY.md#the-web-applications-client), so a CLI party and a browser party follow one set of rules on the wire.
- - -> **A browser run.**
- - -> Its WebRTC wait is one attempt, and the first path failure ends it.
- - -> The failures that send its start are the channel-open bound expiring, on the inviter's open or on the acceptor's dial attempt; the channel failing before it opens, as on ICE failure; a registration with the coordination server failing or not confirmed within its bound with no refusal from it; and the coordination server's socket dropping during the inviter's wait for the partner's connection or the acceptor's dial.
- - -> A browser does not say why a WebSocket failed, so a coordination server certificate it refused is one of these and leaves the exchange to the relays.
- - -> A browser run states the path that carries the exchange in a notice on the run, and logs the rest of the lines above, each relay's refusal included, to the browser's console.
- Channel open | 30 s | The data channel opening once both descriptions are exchanged; reaching it means the peer is present but no candidate pair worked. # meets in Chromium.
