A `"storage"` entry holds `nextRunHeals`, admitted only as `true` and omitted rather than written `false`, where the partner saved the next secret first and completed the key exchange under its [previous secret](PROTOCOL.md#the-previous-secret), which shows that it keeps one: the next run can still reach the partner under the secret this run used. The standing condition and the saved-exchanges list read it at later visits and name the next run, with the re-invite for runs that keep failing, until a later entry records a failed-closed handshake, a failed save without it, or a success; without it they name the re-invite. A build that does not know it reads past it and names the re-invite, which is worse advice rather than a wrong reading, so `schemaVersion` does not move for it. A successful run instead advances `lastRun` to `"succeeded"`; two recoveries drop it: the re-invite, and an apply of a partner's terms change, which drops a `"terms-change"` entry for the same reason ([A refused terms change](#a-refused-terms-change)). Which of two runs' entries the store keeps is [Recording a run outcome](#recording-a-run-outcome).
