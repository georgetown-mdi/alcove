- - -> The WebSocket relay proof
- - -> A party shows a WebSocket relay that it holds the exchange's relay key with a proof made under a key of its own, derived from the relay key as the registrar proof's key is.
- - -> The proof is the message and the tag below; how a relay's hello encodes them is not specified here.
- - -> proof_key = HKDF-SHA-256(ikm = unhex(relay_key), salt = 0x00 * 32, info = "alcove-relay-websocket-v2:proof-key", 32)
- - -> message = "alcove-relay-websocket-v2:hello" LF role LF decimal(expiry)
- - -> tag = HMAC-SHA-256(key = proof_key, msg = ascii(message))
- - -> **The key.**
- - -> The HKDF input is the relay key's 32 decoded bytes, as for the registrar proof, under a label of its own, and the tag is the whole 32-byte MAC.
- - -> So a relay's proof is neither a coturn credential nor a registrar proof, and neither of those is a relay's proof: a captured relay hello mints no TURN credential, and a captured TURN credential opens no relay socket.
- - -> The message starts with a letter, so it never parses as coturn's `<expiry>:<label>` username.
- - -> **The message.**
- - -> Three ASCII fields joined by LF (0x0A), with no trailing LF.
- - -> `role` is the party's rendezvous role, `inviter` or `acceptor` (`RENDEZVOUS_ROLES` in `packages/core/src/rendezvous.ts`).
- - -> `expiry` is decimal Unix seconds with no leading zero, the second from which the relay refuses the proof.
- - -> No field's alphabet admits LF, so the layout parses one way.
- - -> **The expiry bound.**
- - -> A party sets `expiry` to the current Unix second plus whole seconds from 1 to 300 (`WEBSOCKET_RELAY_PROOF_MAX_TTL_SECONDS` in `packages/core/src/websocketRelayProof.ts`), the registrar's freshness window.
- - -> A value outside these bounds is refused rather than clamped.
- - -> As with the TURN credential, the bound covers only the proofs Alcove makes: anyone holding the relay key can make one with a later expiry, and a check does not refuse it.
- - -> **What a check refuses.**
- - -> The relay reads a presented message and tag (`parseWebSocketRelayProof`) and checks them under the proof key of a relay key it holds (`checkWebSocketRelayProof`).
- - -> It refuses a message over 128 bytes, not UTF-8 or not exactly in the layout above, or a tag that is not 32 bytes, as malformed.
- - -> It refuses a role other than the one the presenting party claims, and an expiry at or before its own current Unix second.
- - -> It refuses a tag other than the one the proof key makes over the role and the expiry, compared in constant time.
- - -> A party whose clock runs more than 300 seconds behind the relay's cannot present a proof the relay accepts, and what the relay answers to a stale proof, a server time to sign again as the registrar gives or nothing, is specified with the relay service and not here.
- - -> **The label.**
- - -> `alcove-relay-websocket-v2:*` sits in the [domain-separation label space](#p-256-authenticated-key-exchange).
- - -> Its input keying material is the relay key, not the shared secret, so it gives the relay's operator, who holds the relay key, nothing derived from the secret.
