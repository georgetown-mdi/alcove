# close() waits for the in-progress rendezvous before cleanup(), so an
# interrupted hello publish leaves nothing the next run refuses.
- - -> Before the drain, `close()` waits for the rendezvous still in progress to settle.
- - -> The abort that precedes the wait stops the rendezvous at its next step: every step checks the abort before it starts, whether a directory listing, a hello read, a write or a delete.
- - -> A step already under way finishes, so the wait covers the transport operation in flight together with what completes its step -- a temp write's rename, or the joiner's own hello once it has deleted the peer hello -- and the rollback deletes of a rendezvous that ends without an exchange, and never a further poll interval.
- - -> A write that operation completes lands with its `responsibleFiles` change, whichever write it is: the hello, the rendezvous ack, the `lock`, the joiner's sentinel, or the joiner's step from deleting the peer hello to its own hello.
- - -> A file that lands after a SIGINT or SIGTERM has started teardown is therefore tracked and swept, not left for the next run's entry guard to refuse as this party's own.
- - -> In retain mode an interrupted rendezvous takes the terminal-failure rollback ([I4b](#invariants) (b)), so its own hello and rendezvous ack are removed.
- - -> The wait is bounded like the transport close below, by `RENDEZVOUS_SETTLE_TIMEOUT_MS` (30s) applied as `min(RENDEZVOUS_SETTLE_TIMEOUT_MS, inactivity_timeout_ms)`, internal-only rather than a config setting.
- - -> A write that lands after the bound is left on disk.
- Above those two waits sits the run's own teardown ceiling, **3 min** on both file-based channels: the point at which a finished CLI run stops waiting for its transport to close, whatever is still running beneath. -> Above those waits sits the run's own teardown ceiling, **3 min** on both file-based channels: the point at which a finished CLI run stops waiting for its transport to close, whatever is still running beneath.
- It is above the drain (60 s) and the transport close (30 s) together, with the SFTP adapter's own client-close, forced-close and deferred-cleanup drains smaller again, so reaching it means a close overran every bound beneath it. -> It is above the rendezvous settle (30 s), the drain (60 s), and the transport close (30 s) together, with the SFTP adapter's own client-close, forced-close and deferred-cleanup drains smaller again, so reaching it means a close overran every bound beneath it.
- - -> A `close()` that runs during the rendezvous waits for it to settle before `cleanup()`, and every rendezvous step checks the abort before it starts, so a write in flight lands with its `add` and no step starts after the abort ([Phase 3](#phase-3----cleanup-and-close)); teardown does not open the window either.
