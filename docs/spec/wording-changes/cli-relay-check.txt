- - -> The relay check
- - -> `doctor relay` runs only when it is named: `doctor probe` and `doctor mount` contact no relay and no registrar.
- - -> **Refusals.**
- - -> A configuration whose `connection.channel` is not `webrtc`, one that configures `ice_provision`, and one that lists no TURN url are each a usage error (exit 64), refused before anything is contacted.
- - -> **The host statement.**
- - -> Before its first request, the check prints every TURN url it will ask, with the transport each names and whether it came from `connection.turn` or the invitation.
- - -> It names the first url as the one a run allocates on.
- - -> Where `invitation_relay` names a `registrar`, it also prints that registrar, and states that it enrolls this exchange's relay key there as a run does and that whoever runs the registrar learns this machine's network address; where it names none, the statement says the check contacts no registrar and enrolls nothing.
- - -> It prints them to the destination the human check lines use -- stderr, or the `--log-file` -- with or without `--json`, under `--log-level` as those lines are.
- - -> It contacts those urls and that registrar alone: not `connection.relay_registrar`, no coordination server, and no STUN server.
- - -> **The enrollment.**
- - -> Where `invitation_relay` names a `registrar`, the check enrolls the exchange's relay key there before it asks any relay, through the call a run makes before it dials (`enrollAtInvitationRelay`; [PROTOCOL.md](PROTOCOL.md#enrolling-at-a-default-relay)): one attempt without a token, under the run's wait.
- - -> Its outcome is the `enrollment` check: `ok` with the lapse the registrar states, or `fail` with the run's warning split in two, its first sentence, holding the registrar's answer, as the summary and its second as the `action`.
- - -> The answer is the registrar's text, so it stays in the summary the JSON withholds.
- - -> A `fail` does not stop the check: every url is still asked.
- - -> **The request.**
- - -> For each url the check builds the werift peer connection a run builds, with `ice_transport_policy` `relay` and that url as its only ICE server, presenting what the run presents there: the entry's own `username` and `credential`, or the credential the run mints from the shared secret (`relayCredentialForRun`).
- - -> It creates a data channel and a local offer, and waits for gathering to complete.
- - -> **The bound.**
- - -> Every url is asked at once under one timer of 30 seconds, an arbitrary working value, started once the enrollment has ended.
- - -> A url whose gathering has not completed when it expires is reported as not reached, and its peer connection is closed, ending the gather.
- - -> **The outcomes.**
- - -> A url is reached when a relay candidate is among this side's candidates (the same reading of the ICE statistics a run's failure diagnosis makes).
- - -> The first url's check is `ok` when it is reached, and `fail` otherwise, with `no relay candidate gathered` in the summary and the remedy a run's relay failure has in [CLI.md](../CLI.md#when-a-webrtc-exchange-does-not-connect) as the `action`.
- - -> A later url's check is `ok` when it is reached, and `warn` otherwise, with the same summary, a `meaning` saying a run does not allocate on it, and an `action` to list it first if it should be the run's relay.
- - -> werift reports no per-server error from the peer connection, so a relay that refused the allocation, one that never answered, and one whose certificate did not verify are one outcome, and the `meaning` says the reason is not reported.
- - -> A relay that has not enrolled the exchange's relay key refuses the minted credential, so where the enrollment failed and no run on either side has enrolled the key, an invitation url is not reached on any network, and its check's `meaning` names the failed enrollment as the likely cause.
- - -> **Rollup.**
- - -> Of the url checks, the first alone decides `overall`: its `fail` makes `overall` `fix_and_retry`, and so does a `fail` of the `enrollment` check.
- - -> A later url's `warn` leaves `overall` `ok`.
- - -> The check reports no `skipped` or `fatal`.
