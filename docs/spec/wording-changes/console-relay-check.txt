# The console runs doctor relay over the working folder's pair, states the
# hosts before the spawn, and returns the verdict in the CLI's words.
- - -> `GET` | `/api/jobs/relay-check` | `200` typed envelope | The hosts a relay check of the working folder's `alcove.yaml` and `.alcove.key` would contact and those it would not, read from the file without contacting any: `{ "status": "available", "configurationDigest", "statement", "websocketRelayNotChecked" }`, or `{ "status": "unavailable", "reason", "websocketRelayNotChecked"? }` (see [Checking the relay](#checking-the-relay)). `500` (empty body) on an unexpected fault.
- - -> `POST` | `/api/jobs/relay-check` | `200` typed envelope | Run the CLI's `doctor relay --json` over that pair while `alcove.yaml` is still the file `{ "configurationDigest" }` names (see [Checking the relay](#checking-the-relay)). `400` (empty body) on a bad body, `413` above its size cap, `409` (empty body) when a check is already running, `409` `{ "reason": "exchange-running" }` while an exchange's child is starting or running, `503` (empty body) once the server has begun shutting down, `500` (empty body) on an unexpected fault.
- - -> Checking the relay
- - -> `/api/jobs/relay-check` runs the CLI's [`doctor relay`](CLI_DOCTOR.md) over the working folder's `alcove.yaml` and `.alcove.key`, the pair a webrtc run of this console runs over, so the operator learns whether the relay a run uses gives a relay address from this container.
- - -> The console offers it on the inviter's screens; the endpoint itself reads whichever webrtc configuration the working folder holds.
- - -> The console writes nothing and records nothing; it returns the verdict for the caller to show and forget.
- - -> `GET` reads the pair and contacts nothing.
- - -> It loads `alcove.yaml` through the schema the CLI loads it with, and answers `unavailable` with a closed `reason` where there is nothing to check: `no-configuration`, `configuration-refused`, `not-webrtc`, `ice-provision`, `no-turn-url`, `turn-urls-left-out` (every TURN url is left out by `connection.allowed_relays`), or `key-file` (no usable key file beside it, as [The key file beside an opened configuration](#the-key-file-beside-an-opened-configuration) states).
- - -> Otherwise it answers `available` with the hosts a check contacts and those it does not, composed by core's `relayCheckPlan` and `relayHostStatement` -- the functions the CLI prints its own statement with -- so the hosts the operator is shown before the spawn are the hosts the CLI's plan of the same file contacts.
- - -> `websocketRelayNotChecked` is `true` where a run of the file lists a WebSocket relay, which `doctor relay` does not ask; a file whose only relay is a WebSocket relay is `unavailable` with `no-turn-url` and that flag.
- - -> `configurationDigest` is the SHA-256 of the file's bytes.
- - -> `POST` takes `.strictObject({ configurationDigest })` under a 1 KiB body cap, and re-reads the pair first.
- - -> Where the file's digest is not the one given, it answers `{ "status": "configuration-changed" }` and spawns nothing, so a check runs only over the configuration whose hosts the operator was shown; where the pair is now unavailable, it answers `{ "status": "unavailable", "reason" }`.
- - -> Otherwise the manager spawns `doctor relay --json --config-file=<data root>/alcove.yaml --key-file=<data root>/.alcove.key` under the shared no-shell spawn discipline, with the data root as its working directory, caps its stdout at 64 Ki UTF-16 code units, and discards its stderr, where the CLI writes its own statement and its human lines.
- - -> **The exit is reconciled to a closed set.**
- - -> Exit `0` with an `ok` verdict and exit `78` with a `fix_and_retry` verdict are `{ "status": "verdict", "overall", "checks" }`; exit `64` is `{ "status": "refused" }`, the CLI's refusal of the configuration before it contacted anything; a watchdog kill is `{ "status": "timeout" }`; any other exit, a verdict whose `overall` is not its exit's, an overflowed read, or a line this boundary does not accept is `{ "status": "error" }`.
- - -> **The watchdog sits above the check's own bounds.**
- - -> The child's budget is the check's 30-second request bound plus the invitation relay's 3-second enrollment wait; the watchdog sends SIGTERM at 45 s and SIGKILL after a 5 s grace, so a check that runs to its own bound reports its verdict rather than `timeout`.
- - -> The ordering is held by an arithmetic check over the constants.
- - -> **Each check crosses from closed fields.**
- - -> A check's `id` is `enrollment` or `turn_<n>`, its `status` and `transport` members of their closed sets, its `lapses_at` a UTC timestamp, and the checks' statuses agree with `overall`; a verdict breaking any of these is an `error`.
- - -> Each check crosses as `{ "id", "status", "headline" }`, with the CLI's `meaning` and `action` where the verdict holds them.
- - -> The `headline` is composed by core's `relayCheckHeadline` from the check's closed fields, the function the CLI prints its own summary line with (see [What the verdict withholds](CLI_DOCTOR.md#what-the-verdict-withholds)), so a refused enrollment's headline holds no registrar answer.
- - -> A url or registrar can come from the partner's invitation, so the headline, `meaning`, `action`, and every host and line of the `GET` statement are escaped and bounded by `sanitizeForDisplay` at this boundary and rendered by the UI as given.
- - -> **One check at a time, and never beside a run.**
- - -> One check child runs at a time: a concurrent request is a `409` (empty body), the flag claimed synchronously and independent of the slot.
- - -> A request while the slot's exchange child is starting or running is a `409` `{ "reason": "exchange-running" }`, so a check is not run over the pair a running exchange uses.
- - -> Stated limits
- - -> **A run started during a check is not refused.**
- - -> The check writes nothing in the working folder, so an exchange created while a check runs starts as it would otherwise; the two contact the relay at once.
- - -> **The WebSocket relay is not checked.**
- - -> `doctor relay` asks TURN relays only; the envelope says where a run of the file lists a WebSocket relay, and the console says so beside the hosts.
- - -> **The digest is compared before the spawn, not bound to it.**
- - -> The child reads `alcove.yaml` by path after its digest matched, so an edit made between the two is checked without the operator having seen its hosts; only the operator writes the working folder.
