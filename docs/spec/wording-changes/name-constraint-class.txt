# The name-constraint class is held to the transform patterns' weighted-size cap, checked in the transform patterns' walk under its budget, and the compile cache keeps no pattern over it.
- - -> The conformance check and the size read come from one compile, and the engine's compile cache (`packages/core/src/utils/linearRegex.ts`) keeps only a pattern within the cap, so a pattern refused for size is not retained once its refusal returns; the step editor's pattern check takes the same path.
- - -> One function builds that pattern, the leading-caret escape and the anchoring included (`allowedCharactersPattern`, `packages/core/src/config/transformRegexDialect.ts`), and both the check and the schema below compile what it returns.
- `NameConstraintsSchema` validates the class under that **same engine** at parse time - not `new RegExp` - on every path that decodes partner terms, so a class it accepts is guaranteed to compile at check time and the advisory cannot fail open on a native-versus-RE2 dialect gap; the degenerate empty class, which the engine cannot compile, is rejected there with the existing character-class message. -> The linkage-terms schema checks each name field's class at parse time under that **same engine** - not `new RegExp` - on every path that decodes partner terms, in the same walk as the transform patterns and under the same total budget (`REGEX_DIALECT_TOTAL_BUDGET_MS`), and refuses the document at the first refused class.
- - -> That walk compiles the pattern the check compiles rather than the class as written, so a class it accepts is guaranteed to compile at check time and the advisory cannot fail open on a native-versus-RE2 dialect gap; a class whose built pattern the engine cannot compile, the degenerate empty class among them, is rejected with the existing character-class message, as is a class the walk leaves unchecked when the budget runs out.
- - -> The compile-cost bound is the transform patterns' weighted-size cap (`MAX_TRANSFORM_PATTERN_WEIGHTED_SIZE`, **Weighted-size cap** above), read from that same compile: a class whose built pattern weighs over it is refused with the size message the transform gate states, prefixed by the field name and echoing nothing the partner wrote.
- - -> Measured on this engine build, `A-Z`, `A-Za-z '-`, `\p{L}`, and a class of 256 plain characters each weigh 5 once built.
- - -> Terms holding a class that this check now refuses - one over the cap, or one such as `^]A[` that compiles as written but not once its leading caret is escaped - and that were written before it are refused when read, with no migration.
- `MAX_NAME_LENGTH` (256) is a critical pre-compile length gate on that validation, the compile-cost bound the sibling `MAX_TRANSFORM_PATTERN_LENGTH` is for the transform patterns above. -> `MAX_NAME_LENGTH` (256) is a pre-compile length gate on that validation, as `MAX_TRANSFORM_PATTERN_LENGTH` is for the transform patterns: it bounds the cost of the compile that reads the size.
- Because Zod does not short-circuit chained checks, the refine that compiles `[allowedCharacters]` under re2js runs even on an over-length value, and re2js compile cost is super-linear in source length, so the refine tests the length first and defers an over-length class to the length ceiling's own rejection rather than ever compiling it. -> Because Zod runs the document's checks even when a field has failed its length ceiling, the walk reaches an over-length value, and re2js compile cost is super-linear in source length, so the walk tests the length first and defers an over-length class to the length ceiling's own rejection rather than ever compiling it.
- Both count the same code units (`maxCodeUnits`), so no class the refine waves through on that length test is admitted by the ceiling. -> Both count the same code units (`maxCodeUnits`), so no class the walk waves through on that length test is admitted by the ceiling.
