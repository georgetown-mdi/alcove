- A header recognized as an identifier only once folded, such as `ID ` with a trailing space, is declared and sent on a configuration with no `metadata` block, and a partner whose `payload.receive` is unset takes that wider set on its first run as it takes any first-run set ([An unset `payload.receive` is filled on the first run](EXCHANGE_FILE.md#an-unset-payloadreceive-is-filled-on-the-first-run)). -> A header recognized as an identifier only once folded, such as `ID ` with a trailing space, is declared and sent on a configuration with no `metadata` block when it is the header's first `identifier`-typed column, and a partner whose `payload.receive` is unset takes that wider set on its first run as it takes any first-run set ([An unset `payload.receive` is filled on the first run](EXCHANGE_FILE.md#an-unset-payloadreceive-is-filled-on-the-first-run)).
- A second pass then decides which column indexes this party's own records: a header with exactly one `identifier`-typed column promotes that column to `role: identifier` whatever its name, and a header with several leaves the promotion to a column whose lookup key is `id` or `identifier` if one is present, and to no column at all otherwise. -> A second pass then decides which column indexes this party's own records: the first `identifier`-typed column in header order is promoted to `role: identifier` whatever its name.
- - -> Every later `identifier`-typed column, whichever row typed it, infers nothing when declared-only, and `role: payload`, `is_payload: true` in direct mode.
