- - -> `set-over-limit` | `stage` (one of `before-contact`, `after-terms`, `in-round`), `limit` (one of `set-maximum`, `partner-ceiling`, `uncounted`), and for `set-maximum` or `partner-ceiling`: `valueCount` and `limitValues` (each a non-negative integer) and `scope` (optional; one of `first-key`, `every-key`, `widest-key`) | A set of this party's own was refused before it was sent: at the start of the exchange (`before-contact`), after the terms exchange before any linkage key was sent (`after-terms`), or inside a round (`in-round`). `valueCount` is the values the set holds and `limitValues` the limit it is over: the most one PSI set can hold (`set-maximum`), or the most the partner stated it can receive (`partner-ceiling`, [PROTOCOL.md](PROTOCOL.md#the-receive-ceiling)). `scope` names the rounds a first round's count covers, and is absent for one linkage key's set. `uncounted` states that the first round's values could not be counted, and holds no count.
- - -> **Limit: an uncounted set's report keeps one line of its count failure.**
- - -> When the first round's values could not be counted, the console's reported-cause block ends the count failure at the first escaped line break after the last cause link, which is how it leaves out the CLI's next step; a count failure whose own message spans lines is shown only up to its first line break.
