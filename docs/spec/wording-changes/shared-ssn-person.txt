- - -> Where the party's own terms set `deduplicate`, the `ssn` screen also reaches the `ssn4` field read from the same column (see [Last four derived from a full SSN](#last-four-derived-from-a-full-ssn)): a record whose `ssn` value the screen drops has no `ssn4` value either.
- - -> Where they do not, the record keeps its `ssn4` value.

- - -> An `ssn4` field read from a column of its own is not screened.
- A person is a record's cleaned `first_name`, `last_name` and `date_of_birth` values. -> A person is a record's cleaned `first_name` and `date_of_birth` values.
- - -> The last name takes no part in the count, so a person whose last name differs between records, after a marriage or a keying error, is still one person.
- Records holding the same three values are one person, so a person's own duplicate records count once. -> Records holding the same two values are one person, so a person's own duplicate records count once, whatever last name each holds.
- A record missing one or more of the values, because its cell was empty or its pipeline dropped the value, is the same person as a record that holds the same value of the field, agrees with it on every value it has, and has a value it lacks. -> A record missing one or both of the values, because its cell was empty or its pipeline dropped the value, is the same person as a record that holds the same value of the field, agrees with it on every value it has, and has a value it lacks.
- When the file has none of the three columns, every record holding a value is one person, and the screen drops nothing. -> When the file has neither column, every record holding a value is one person, and the screen drops nothing.
- A record with neither a name nor a date of birth agrees with every holder of its value, so it never counts as another person. -> A record with neither a first name nor a date of birth agrees with every holder of its value, so it never counts as another person.
- A person's own duplicate record whose cleaned name differs, such as a spelling variant, counts as another person, so a value can be dropped from one person's records. -> A person's own duplicate record whose cleaned first name differs, such as a typo or a nickname, counts as another person, so a value can be dropped from one person's records.
- - -> The count compares cleaned values exactly, so it recognizes neither.
- - -> A record holding `MARIA`, `GARCIA`, `19800101` beside the first is the same person, and the SSN is kept: the last name is not compared.
- A record holding `MARIA`, `LOPES`, `19800101` beside the first is another person: the count compares cleaned values and corrects no spelling. -> A record holding `MAIRA`, `LOPEZ`, `19800101` beside the first is another person: the count corrects no spelling.
