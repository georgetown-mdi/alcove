Only the window's own bookkeeping write sets it, and only for a window that made an attempt: the refusal form where the window's latest attempt that tried to enroll at the default relay failed there, the none form where that attempt's enrollment confirmed or no attempt tried. A window that made no attempt leaves it as it is. It is this device's alone, as `heldAppUpdate` is: an export does not include it, a new or imported record starts at the none form, and a replace keeps the stored one. The field is **required**, for the reason `standingCondition` is.
