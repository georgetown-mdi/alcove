# The relay test on the web application's Relay server page.
- - -> Testing the browser's relays
- - -> The web application's Relay server page tests whether this browser reaches each relay a browser run lists (`apps/web/src/psi/transport/relayTest.ts`).
- - -> It tests reachability only: whether each relay answers this browser over each transport, not whether a relayed path between the two parties passes data.
- - -> **When.**
- - -> Only when the user starts it.
- - -> Before it contacts anything, the page lists each url it will contact, with its source and the transport it names, and states that whoever runs each relay learns this browser's network address.
- - -> Loading the page and saving a setting contact no relay.
- - -> A browser without `RTCPeerConnection` is offered no test, and the page states that this browser cannot run it.
- - -> While the test runs, the page announces how many relays it tests and the bound.
- - -> **What it contacts.**
- - -> The TURN urls of this browser's saved relay setting, then the build's default relay's TURN url, each once, in the order a run lists them ([Which relay a run uses](#the-invitations-relay-locator)).
- - -> A setting this build cannot read adds nothing, as for a run.
- - -> An edit not yet saved is not tested, and the page says so while the TURN field differs from the saved setting.
- - -> The invitation's relay is not known on that page, so it is not listed.
- - -> No STUN url, no registrar and no coordination server is contacted.
- - -> **The default relay.**
- - -> A run lists the default relay only once its enrollment at the relay's registrar confirms ([Enrolling at a default relay](#enrolling-at-a-default-relay)).
- - -> The test asks the relay without that enrollment and contacts no registrar, so it enrolls nothing and uses none of the registrar's enrollments for this client address.
- - -> **The request.**
- - -> Each url on a peer connection of its own, with that url as its only ICE server, the `relay` transport policy, a data channel and a local offer.
- - -> It presents a placeholder credential: the username `alcove-relay-test` and 16 random bytes in hex, drawn afresh for each url.
- - -> No credential is derived from a shared secret, and a relay holding only exchange keys refuses it.
- - -> **The bound.**
- - -> Each url is waited on for at most 30 seconds (`RELAY_TEST_BOUND_MS`, an arbitrary working value, the CLI relay check's own).
- - -> Its peer connection is closed when its result is known, when gathering ends, at the bound, or when the user leaves the page.
- - -> **The outcomes.**
- - -> One per url and transport: the transport the url names (`turns:` is TLS, `turn:` with `transport=tcp` is TCP, any other `turn:` url UDP), and any other transport the browser reports an error for on that url.
- - -> **Answered.**
- - -> The browser reported a 401 for it, the relay refusing the placeholder credential, or gathered a relay candidate over it.
- - -> **Refused.**
- - -> The browser reported any other STUN error code (300 to 699), the relay answering with a reason other than the credential.
- - -> **No answer.**
- - -> The browser reported an error with any other code or with none, such as error 701, or reported nothing before the bound expired or gathering ended.
- - -> **Not tested.**
- - -> The browser refused the url when the peer connection was built, with a `SyntaxError` or `NotSupportedError`, or failed while setting up that url's test.
- - -> **The wording.**
- - -> Each result is written as a test result over its transport, never as an exchange failure.
- - -> An answer and a refusal each state that this browser reaches the relay over that transport, and the page states that the test does not show that the relay passes an exchange's traffic.
- - -> A failure states its reason, the browser's error code and text or the bound, and a remedy.
- - -> For no answer it is the remedy an exchange's relay failure gives ([DEPLOYMENT.md](../DEPLOYMENT.md#a-relay-that-could-not-be-reached)), to check the relay's address and that this network allows connections to it; for a refusal, to check the relay's settings for that error or ask whoever runs it.
- - -> Either ends with running the test again.
- - -> No answer when gathering ended adds that a relay that refused the credential shows the same when the browser does not report the refusal.
- - -> A url whose test could not be set up, or a test that failed as a whole, asks the user to reload the page and run it again.
- - -> The browser's error text is escaped for display and bounded to 200 characters.
- - -> **Stated limits of the test.**
- - -> **The 401 is unconfirmed.**
- - -> That Chromium reports a 401 for a refused credential before it gives up on the transport is to be confirmed on a real browser run against a TURN server.
- - -> The unit tests mock the peer connection, and the browser suite drives real Chromium only against a relay whose name does not resolve, which Chromium reports as error 701.
- - -> Where Chromium reports no 401, a relay that answered shows as no answer.
- - -> **An answer is not a working relay.**
- - -> It does not show that the relay holds the exchange's key, or that a relayed path passes data.
