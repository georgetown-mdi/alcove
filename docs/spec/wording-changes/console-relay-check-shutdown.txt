# Shutdown stops every CLI child the server spawns, not only the exchange's
# and the relay check's.
- On server shutdown (`SIGINT`/`SIGTERM`), the server stops accepting connections and closes its idle ones, then runs its `close` hooks: the job manager's sends the active exchange's running child and a running relay-check child `SIGTERM`, and `SIGKILL` to each still running after the cancellation's `SIGKILL` grace (5 s), and resolves only once each child's exit has been observed. -> On server shutdown (`SIGINT`/`SIGTERM`), the server stops accepting connections and closes its idle ones, then runs its `close` hooks: the job manager's sends `SIGTERM` to every CLI child the server has running -- the active exchange's child and a child of the host-key probe, the signing fingerprint, the terms apply, or the relay check -- and `SIGKILL` to each still running after the cancellation's `SIGKILL` grace (5 s), and resolves only once each child's exit has been observed.
- It signals no child when the API was never enabled or neither an exchange nor a relay check is running. -> It signals no child when the API was never enabled or none of these children is running, and a child that has already exited, or never started, does not delay the shutdown.
- `apps/web/test/unit/jobs/jobShutdown.unit.test.ts` drives the wiring through the console server's own graceful shutdown (`apps/web/server/console/shutdown.ts`). -> `apps/web/test/unit/jobs/jobShutdown.unit.test.ts` drives the exchange, host-key probe, signing fingerprint, and terms apply children through the console server's own graceful shutdown (`apps/web/server/console/shutdown.ts`).
