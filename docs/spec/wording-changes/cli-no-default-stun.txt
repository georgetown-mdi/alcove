# A CLI run listing only TURN urls asks no STUN server: every non-empty ICE
# server list ends with an IPv6 loopback STUN entry werift never queries. The
# pins record the werift behaviour that makes it work and the tests that hold it.
- **A configured `iceServers` list replaces werift's built-in `stun.l.google.com:19302` default rather than adding to it.** -> **A configured `iceServers` list holding a `stun` url werift can parse replaces werift's built-in `stun.l.google.com:19302` default rather than adding to it.**
- An empty or absent list means "use the default" (it does not mean "no STUN"), and `getConfiguration()` echoes its input, so it confirms pass-through but not suppression. -> An empty or absent list means "use the default" (it does not mean "no STUN"), and so does a list naming only TURN urls, and `getConfiguration()` echoes its input, so it confirms pass-through but not suppression.
- - -> **werift queries a STUN server from IPv4 sockets only, and refuses an IPv6 literal target there before any lookup or send.**
- - -> A list ending with `stun:[::1]:9` (`UNQUERIED_STUN_URI` in `apps/cli/src/connection/webrtc/weriftPeer.ts`) therefore never contacts that entry, and gathers no server-reflexive candidate where it names no other `stun` url; a `stun` url ahead of it is the one werift takes.
- - -> Every non-empty list a CLI run builds ends with it, so a run that lists only TURN urls asks no STUN server instead of the default.
- - -> Measured on werift 0.25.0 with every DNS lookup and UDP send recorded:
- - -> A peer listing only that entry looks nothing up and sends nothing, and gathers its host candidate within milliseconds; an unanswered IPv4 entry such as `stun:127.0.0.1:9` instead holds gathering on werift's 5 s STUN timer.
- - -> A peer listing a loopback TURN server and that entry contacts the TURN server alone, and gathers its relay candidate as quickly; the same list without the entry looks up the default.
- - -> Two peers listing a TURN server and that entry connect over host candidates.
- - -> The integration test (`test/integration/webrtc/firstTurnUrl.test.ts`) asserts the second through the CLI's own configuration, and the transport suite the third.
