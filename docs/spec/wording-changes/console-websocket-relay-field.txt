# The console's coordination server card sets a WebSocket relay beside the
# TURN urls: PUT /api/jobs/webrtc takes it in ownRelay, an inviter's run
# states it as websocket_relay, and the console's invitation names it with
# the registrar's exchange id, as alcove invite does.
- An inviter's run states the authored server's `ownRelay`, where it has one: each of its `turn` urls as a `turn` entry holding only `url`, whose credential the CLI mints from the shared secret on each run, and its `relayRegistrar` as `relay_registrar`. -> An inviter's run states the authored server's `ownRelay`, where it has one: each of its `turn` urls as a `turn` entry holding only `url`, whose credential the CLI mints from the shared secret on each run, its `websocket` url as `websocket_relay`, and its `relayRegistrar` as `relay_registrar`.
- An acceptor's `relay` must equal the authored `invitationRelay`, both absent included, and an inviter's must hold only a `turn` list of the authored `ownRelay`'s `turn` urls in order, or be absent where none is authored; otherwise the create is the same `400`. -> An acceptor's `relay` must equal the authored `invitationRelay`, both absent included, and an inviter's must equal the locator the console's invitation names for the authored `ownRelay` (below), or be absent where none is authored; otherwise the create is the same `400`.
- The body is `{ "address": "<text>", "invitationRelay"?: { "turn"?: [ "<url>" ], "stun"?: [ "<url>" ] }, "ownRelay"?: { "turn": [ "<url>" ], "relayRegistrar"?: { "url", "exchangeId" } } }`, strict, read under a 16 KiB cap (`413` above it), with `address` at most 2048 code units (core's `MAX_SIGNALING_SERVER_URL_LENGTH`). -> The body is `{ "address": "<text>", "invitationRelay"?: { "turn"?: [ "<url>" ], "stun"?: [ "<url>" ] }, "ownRelay"?: { "turn"?: [ "<url>" ], "websocket"?: "<url>", "relayRegistrar"?: { "url", "exchangeId" } } }`, strict, read under a 16 KiB cap (`413` above it), with `address` at most 2048 code units (core's `MAX_SIGNALING_SERVER_URL_LENGTH`).
- A strict object holding `turn`, a list of 1 to 8 url strings (core's `MAX_RELAY_LOCATOR_URLS`), each at most 1024 code units and held to core's `TurnUrlSchema`, and optionally `relayRegistrar`, held to core's `RelayRegistrarSchema`. -> A strict object holding `turn`, a list of 1 to 8 url strings (core's `MAX_RELAY_LOCATOR_URLS`), each at most 1024 code units and held to core's `TurnUrlSchema`, `websocket`, one url string held to core's `webSocketRelayUrlSchema`, the rule of `connection.websocket_relay`, or both, and optionally `relayRegistrar`, held to core's `RelayRegistrarSchema`.
- - -> **A registrar needs a TURN url.**
- - -> A `relayRegistrar` beside no `turn` list is refused, as core's schema refuses a `connection.relay_registrar` beside no url-only `turn` entry, so a WebSocket relay alone is set with no registrar.
- - -> **The invitation names it as `alcove invite` names a configuration's own relay.**
- - -> The locator holds the `turn` urls in order, the `websocket` url, and beside that url, as `websocketExchangeId`, the `relayRegistrar`'s `exchangeId`, which the relay holds the key under (`ownRelayInvitationLocator` in `apps/web/src/jobContract/signalingServer.ts`).
- - -> The registrar's address is this party's own and is not named.
- - -> A console names the WebSocket relay set with its coordination server instead, which its run states as `websocket_relay` (`ownRelayInvitationLocator` in `apps/web/src/jobContract/signalingServer.ts`).
- The CLI names its `relay_registrar`'s `exchange_id` beside the `websocket_relay` it names (`endpointFromConnection`), and the web app names a saved exchange's registrar's exchange id (`relayRegistrar`) beside the browser's own WebSocket relay url on a re-invite (`composeManagedReinvite` in `apps/web/src/psi/managed/managedReinvite.ts`); neither names one otherwise. -> The CLI names its `relay_registrar`'s `exchange_id` beside the `websocket_relay` it names (`endpointFromConnection`), a console names its registrar's exchange id beside the WebSocket relay set with its coordination server (`ownRelayInvitationLocator`), and the web app names a saved exchange's registrar's exchange id (`relayRegistrar`) beside the browser's own WebSocket relay url on a re-invite (`composeManagedReinvite` in `apps/web/src/psi/managed/managedReinvite.ts`); none names one otherwise.
