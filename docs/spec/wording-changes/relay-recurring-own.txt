# A saved (recurring) exchange keeps its own allowed relays on its record's
# connection, edited on its page as a local setting of the document, applied
# by its runs and re-invites, and held through the command-line export and
# import and the backup.

A record stored before that rule holds no delimiter: it was read by detection and now reads as a comma, with no `schemaVersion` change, so a recurring exchange whose input is not comma-separated fails closed at its next window, with the single-column delimiter remedy stated at launch. It has **no `authentication` block** (the secret lives in `sharedSecret` below) and is composed exactly as the mint layer composes a downloadable file: assembled from a credential-free locator input, validated through the shared schema, with the **parse result** (never the raw input) persisted. The record stores the document as minted, or as the operator last edited its local settings, so the content guidance for these fields is the same **operator cooperation** the `label` row describes, and no additional bound or strip pass runs at persist time: the document is kept verbatim, and a document the mint layer accepts must remain saveable as managed (see [Metadata at rest](../SECURITY_DESIGN.md#metadata-at-rest-presence-and-shape)). The document's connection is fixed for the partnership, and a re-invite re-issues the document verbatim with only a fresh secret. - - -> **Allowed relays.**
- - -> Core's entry rule is their only bound: the count and length bounds of the browser's stored Allowed relays do not apply to a record.
- - -> An empty list keeps no TURN url, so the record's runs use no relay; the editor shows it as an empty field with a line stating so, a save leaves it while the field stays empty, and entered relays replace it.
- - -> While the document holds a list, empty or not, the editor offers a control that removes it: a save with that control set drops the field, so the record's runs use every relay they list.
- - -> The allowed-relays control is offered only on a webrtc connection; elsewhere a save leaves the connection as it is.
- - -> Each run, and each re-invite, applies the record's `allowedRelays` in place of the browser's Allowed relays on its Relay server page, as [PROTOCOL.md](PROTOCOL.md#the-invitations-relay-locator) states the setting.
