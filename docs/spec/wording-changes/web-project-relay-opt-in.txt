# A build may offer its default relay switched off until the browser's user
# turns it on; switched off, a run uses each of its urls only where the
# invitation it accepted names that url.
- - -> The build offers the relay switched off until the browser's user turns it on, or turns it on in every browser run (`VITE_DEFAULT_RELAY_MODE`, `opt-in` or `on`).
- - -> Switched off, a run uses each of the relay's urls only where the invitation it accepted names that url: the TURN url, and the enrollment below, only where the invitation names the TURN url, and the WebSocket relay url only where the invitation names the WebSocket relay url (`defaultRelayForRun` in `apps/web/src/psi/transport/defaultRelay.ts`).
- Each browser run of such a build enrolls its relay key there right before it connects, and lists the relay once enrolled; the client is `enrollRelayKeyWithoutToken` in `packages/core/src/relayRegistrarClient.ts`, and the browser's side `apps/web/src/psi/transport/defaultRelay.ts`. -> Each browser run of such a build that uses the relay enrolls its relay key there right before it connects, and lists the relay once enrolled; the client is `enrollRelayKeyWithoutToken` in `packages/core/src/relayRegistrarClient.ts`, and the browser's side `apps/web/src/psi/transport/defaultRelay.ts`.
- Every browser run, inviter or acceptor, one-shot or managed, right before it contacts the coordination server; a managed run enrolls after its retry of a pending registration. -> Every browser run that uses the relay, inviter or acceptor, one-shot or managed, right before it contacts the coordination server; a managed run enrolls after its retry of a pending registration.
- Creating an invitation, a one-shot invitation or a managed re-invite, enrolls nothing, and the invitation names the default relay whatever its registrar would answer ([The invitation's relay locator](#the-invitations-relay-locator)). -> Creating an invitation, a one-shot invitation or a managed re-invite, enrolls nothing, and an invitation created with the relay in use names it whatever its registrar would answer ([The invitation's relay locator](#the-invitations-relay-locator)).
- - -> One created with the relay switched off names neither it nor its registrar.
- The TURN urls of this browser's saved relay setting, then the build's default relay's TURN url, each once, in the order a run lists them ([Which relay a run uses](#the-invitations-relay-locator)). -> The TURN urls of this browser's saved relay setting, then the default relay's TURN url where this browser uses that relay, each once, in the order a run lists them ([Which relay a run uses](#the-invitations-relay-locator)).
- A confirmed enrollment also lists the default relay's WebSocket relay url, where the build names one and the allowed relays keep it, after the browser's own and the invitation's ([Which WebSocket relays the allowed relays keep](#the-invitations-relay-locator)), and an unconfirmed one leaves that url out too. -> A confirmed enrollment also lists the default relay's WebSocket relay url, where the build names one, the run uses it and the allowed relays keep it, after the browser's own and the invitation's ([Which WebSocket relays the allowed relays keep](#the-invitations-relay-locator)), and an unconfirmed one leaves that url out too.
- - -> A run with the relay switched off whose invitation names the WebSocket relay url and not the TURN url enrolls nowhere, and lists that url as the invitation's.
